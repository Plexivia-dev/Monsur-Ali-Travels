### MD02: Standalone Architecture Migration & Core Infrastructure Setup in Admin

- **Date**: 2026-08-14
- **Impact**: Admin SPA (`admin/`), Docker Configuration, State Management, API & Error Handling
- **Description**: Migrated core operational infrastructure into the standalone single-tenant `admin` project (abandoning multi-client config-based complexity in favor of direct client-focused architecture). Configured single-tenant Axios API client with token refresh & interceptors, global Sonner toast error handling, Zustand application state store, and Dockerfile/Nginx containerization for production deployment.
- **Changes**:
  - Added [`admin/src/lib/api-client.ts`](file:///f:/Monsur%20Ali%20Travels/admin/src/lib/api-client.ts) supporting dynamic environment baseURLs, automatic bearer token injection, and queued 401 token refresh.
  - Added [`admin/src/lib/error-handler.ts`](file:///f:/Monsur%20Ali%20Travels/admin/src/lib/error-handler.ts) and [`admin/src/lib/utils.ts`](file:///f:/Monsur%20Ali%20Travels/admin/src/lib/utils.ts) for sanitized user notification triggers.
  - Added [`admin/src/store/useAppStore.ts`](file:///f:/Monsur%20Ali%20Travels/admin/src/store/useAppStore.ts) using Zustand for unified portal navigation, sidebar state, search modal, and session management.
  - Added production Docker build files [`admin/Dockerfile`](file:///f:/Monsur%20Ali%20Travels/admin/Dockerfile), [`admin/nginx.conf`](file:///f:/Monsur%20Ali%20Travels/admin/nginx.conf), and [`admin/.dockerignore`](file:///f:/Monsur%20Ali%20Travels/admin/.dockerignore).
  - Updated all root Docker Compose profiles ([`docker-compose.yml`](file:///f:/Monsur%20Ali%20Travels/docker-compose.yml), [`docker-compose.prod.yml`](file:///f:/Monsur%20Ali%20Travels/docker-compose.prod.yml), [`docker-compose.dev.yml`](file:///f:/Monsur%20Ali%20Travels/docker-compose.dev.yml), [`docker-compose.stage.yml`](file:///f:/Monsur%20Ali%20Travels/docker-compose.stage.yml)) to build and serve from `./admin`.
